# IQ3_S aligned 112-byte copy trial on Apple M5, 2026-10-11

Both private layouts preserve the measured outputs and canonical states,
but lose throughput in paired decode screening. Neither is adopted;
production keeps the original GGUF layout and shaders.

The copy rearranges each 110-byte IQ3_S block into 112 bytes: FP16 scale at
0, two zero padding bytes, four scale bytes at 4, eight high-quant bytes at
8, 64 payload bytes at 16 and 32 sign bytes at 80. Blocks and headers are
16-byte aligned, payload subblocks 8-byte aligned and signs 4-byte aligned.
Every source byte is compared against the prepared copy; guards surround
each allocation. Variant 1 reads scalar bytes from this layout; variant 2
reads a `uint4` header, `uint2` payload and `uint` signs. Both keep the
native FP32 expressions, per-row K order, grid representation, SIMD
reductions and eight-row dispatch geometry for single and paired matvecs.

Each variant passes 36 guarded matrix cases: six shapes × three input
patterns × single/pair operations. All outputs are finite and byte-identical,
input bytes remain unchanged and native/packed output guards pass. Metal API
validation is enabled. Alternate shapes reinterpret bounded real FFN tensor
prefixes; they are not all actual model dimensions.

| Variant | Baseline token/s | Candidate token/s | Throughput change |
| --- | ---: | ---: | ---: |
| 1, scalar loads | 9.13409 | 9.10148 | −0.357% |
| 2, aligned vector loads | 9.11329 | 9.06221 | −0.561% |

Each screening uses two ctx512 sessions with the same synthetic 128-token
prefix, then 72 greedy forward pairs in alternating AB/BA order. The first
eight are untimed and all remaining 64 pairs are retained. Full-vocabulary
finite byte equality is checked after every forward, outside timing;
canonical K/V, DeltaNet, convolution state and token history match before
and after the sequence. Hard counters require 5,256 candidate single
dispatches, 1,368 paired dispatches and 7,992 redirected weight bindings per
run. Encoder/command-buffer boundaries and production FAST/K64/GDN defaults
are retained. This is a private screening, not ordinary single-session
throughput or a direct llama comparison.

The model's 111 IQ3_S tensors are copied once into 3,592,035,264 bytes of
Shared buffers, including allocation guards. The original GGUF stays mapped;
this entire copy is additional memory, not just the two padding bytes per
block. Preparation takes 1.102 s and 0.579 s in the two runs and is outside
timing. Both sessions share the same prepared allocations. Swap usage rises
from 807.06 to 1,573.12 MiB across the first screening and remains at
1,573.12 MiB across the second. Startup, preparation and inference all fall
between these observations; the data do not attribute the increase to a
particular stage. This additional-memory approach does not establish a useful
speed improvement. No claim about temperatures, physical resident memory or
clocks follows from the swap observations.

The launcher clears QW3/GGML/MTL overrides, sets full 64-layer offload and
F16 KV, and waits 30 seconds before each screening. All frozen source and
binary hashes match after the runs. Both final targets compile without
warnings. No full eight-prefix/checkpoint suite or ordinary native performance
campaign is run after the negative screenings.

The [manifest](measurements/iq3_layout_2026-10-11/manifest.json),
[derived results](measurements/iq3_layout_2026-10-11/analysis.json),
72 matrix cases, 128 timed pairs, build logs, complete streams and immutable
source snapshot are retained. Reproduction uses the optional
`qw3-iq3-layout-test MODEL VARIANT` and `qw3-iq3-layout-bench MODEL VARIANT`
targets, with variants 1 and 2. Full-quality entry points remain private.
