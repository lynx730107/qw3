# IQ3_S integer sign-folding trial on Apple M5, 2026-10-11

Both private single-matvec variants fail the required bit-for-bit check and
are rejected before timing. Production inference is unchanged.

The trial folds the ±1 sign into the decoded integer magnitude before
converting to FP32, eliminating a floating-point sign multiplication. Variant
1 uses the native implicit accumulation expression; variant 2 uses explicit
`fma` for accumulation. Input loads, block scaling, K traversal, row geometry
and SIMD reduction are retained. Mathematical equivalence of a sign change
does not establish identical compiled floating-point evaluation.

| Variant | First failing case | Reference bits | Candidate bits | ULP distance |
| --- | --- | --- | --- | ---: |
| 1, implicit accumulation | 256→1, dynamic-range input | `423e8c0a` | `423e8c08` | 2 |
| 2, explicit FMA | 256→1, mixed finite input | `3e8736de` | `3e8736df` | 1 |

The intended guarded matrix suite covers six shapes and three input patterns:
mixed finite values, signed zeros and varied magnitudes. Every completed
case checks finite outputs with byte equality, output guards and unchanged
input bytes. Variant 1 passes two cases before failing its third; variant 2
fails its first. Each stops at the first difference. Both runs use the real
IQ3_S FFN weight bytes from `Qwen3.8-27B-UD-Q3_K_XL.gguf`, with Metal API
validation enabled and environment overrides cleared.

Both test executables compile without warnings. The full-model/checkpoint
and paired timing entry points are available for reproduction but are not
run after the matrix failures. There is no performance result and no claim
of model-state or checkpoint correctness for these candidates.
