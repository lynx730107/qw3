# IQ3_S private-buffer screening on Apple M5, 2026-10-11

Private copies preserve the tested IQ3_S outputs and model states, but the
measured benefit is small and not independently confirmed for ordinary
decode. No production change is adopted from this campaign. The buffers add
3.53 GB while paired gains shrink from +0.105% to +0.022%; ordinary screening
has a +0.464% point estimate with only two ON blocks.

All 111 IQ3_S tensors retain their original 110-byte block format. The
candidate uses distinct pipeline objects created from the same functions
in the already-compiled native library. No modified Metal shader is compiled.
Only weight bindings change from the original mapped Shared buffer to
copies in Private storage. GPU blits initialize the copies and a complete
GPU-to-CPU readback compares every payload byte with the original. Allocation
guards, including padding, are verified; subsequent GPU guard readbacks run
outside timing. Temporary Shared staging allocations are released during
preparation.

Thirty-six matrix cases pass finite byte equality with Metal API validation
enabled: six shapes × three input patterns × single/pair operations. Input
bytes remain unchanged and output/private-buffer guards pass. Alternate
shapes reinterpret bounded real FFN tensor prefixes.

| Paired screening | Baseline token/s | Candidate token/s | Change |
| --- | ---: | ---: | ---: |
| First | 8.84516 | 8.85443 | +0.105% |
| Replication | 8.84729 | 8.84925 | +0.022% |

Each uses two ctx512 sessions with the same 128-token synthetic prefix,
followed by 72 greedy AB/BA forward pairs. The first eight are untimed; all
64 remaining pairs are retained. Every full-vocabulary vector is finite and
byte-identical after every forward. Canonical history, K/V, DeltaNet and
convolution states match before and after each sequence. Counters require
5,256 single and 1,368 paired candidate dispatches, plus 7,992 redirected
weight bindings per run. Eight-token saved-time block means have both signs.
Descriptive block-t radii are ±0.270 and ±0.369 ms around means +0.118 and
+0.025 ms/token; block independence is not established, so these are not
promotion tests. Swap remains 1,565.12 MiB across each paired run.

The ordinary benchmark then uses one ctx256 session, tg32 at depth128,
three repetitions per block and the stock warmup/token/timing code. Five
blocks run OFF/ON/OFF/ON/OFF with 30 seconds idle before every process. OFF
allocates no weight copies; ON enables the copies before warmup. Prefix
setup, preparation, payload capture and final guards are outside timing.
All 15 samples are retained.

| Ordinary aggregate | OFF | ON |
| --- | ---: | ---: |
| Token/s from mean elapsed time | 8.84024 | 8.88130 |
| Spread of block mean elapsed times | 0.866% | 0.190% |

The +0.464% ordinary point estimate does not establish a repeatable gain.
The first ON block improves +0.904% against its preceding OFF but only
+0.035% against its following OFF. The second improves +0.225% and +0.359%
against its two neighbors. Both modes pass the ≤5% spread gate,
but this small series contains only two ON blocks, has unequal adjacent
effects and lacks independent ordinary replication. These are private
benchmark controls, not a production-binary confirmation or a llama
comparison. Each ON process records 8,924 candidate dispatches and 10,767
redirected bindings; OFF records zero and allocates no copies. Swap is
1,557.12 MiB before and after all five ordinary blocks.

Each preparation allocates 3,527,891,904 bytes, including guards and padding,
and takes about 1.12–1.14 s. The recorded Metal `currentAllocatedSize` rises
from 13,137,182,720 to 16,666,312,704 bytes before sessions are created; this
does not measure physical resident RAM. No temperature/clock constancy is
established. All runs use the same GGUF, full 64-layer offload, F16 KV and
native FAST/K64/GDN defaults. QW3/GGML/MTL overrides are cleared by the
launcher; requested threads are four, which does not establish qw3's CPU
helper count. All final targets compile without warnings.

Reproduce with optional targets `qw3-iq3-private-test MODEL 1` and
`qw3-iq3-private-bench MODEL 1`. The ordinary target is
`qw3-iq3-private-native-bench`, using `QW3_METAL_IQ3_PRIVATE=0` or `1` and
the full commands/configuration recorded in the manifest.
