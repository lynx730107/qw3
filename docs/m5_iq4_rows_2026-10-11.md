# IQ4_XS row reuse on Apple M5

Four and eight output rows per SIMD group preserve exact results but show
no useful decode gain in this screening. The existing two-row geometry
remains in production. These private variants target the large IQ4_XS
contribution in the [native pipeline profile](m5_native_decode_profile_2026-10-10.md).

Each variant reuses the native four activation vectors across more rows.
The packed weights, 16-value shared table, two SIMD groups, 64 threads,
lane mapping, K-block loop, FP32 dot helper, per-row accumulation and SIMD
reduction remain unchanged. A private host adapter selects the candidate
pipeline and adjusts the number of threadgroups; command boundaries remain
native. The adapter's bookkeeping is present in both paired controls.

Both variants pass 36 guarded matrix cases each: six shapes, three kernels
(single, gate/up pair, residual add), mixed finite activations and signed
zeros. Every float is finite and bit-identical, output guards are exact and
input bytes unchanged. Shapes include odd output counts and are the same
bounded real-weight reinterpretations as the
[aligned-load screening](m5_iq4_loads_2026-10-11.md). Metal API validation is
enabled for these matrix checks.

Paired model screening uses ctx512, all 64 layers on Metal, F16 KV, native
FAST/K64/GDN cache64, a 128-token synthetic prefix (seed 1), and 72 greedy
forward pairs alternating AB/BA. The first eight pairs are warmup; 64 pairs
per variant are timed after a 30-second initial pause. Numerical checks are
outside the forward timer and API validation is disabled for timing. The
engine receives `n_threads=4`; this does not establish CPU helper thread count.

| Rows per SIMD | Baseline / candidate, token/s | Change |
| --- | ---: | ---: |
| 4 | 9.15919 / 9.05613 | −1.125% |
| 8 | 9.13012 / 8.97734 | −1.673% |

All finite full-vocabulary logits are bit-exact after the prefix and each
forward. Canonical history, live K/V, DeltaNet and convolution state are exact
before and after the sequence. Each variant executes 10,224 candidate
dispatches: 72 × (96 single + 14 pair + 32 add). Neither short paired rate
is ordinary single-session throughput or a comparison with llama.cpp.

A follow-up isolates seven actual IQ4_XS decode shapes, covering the 142
dispatches per step, using OFF/rows4/OFF/rows8/OFF controls and eight ordered
GPU replays per command. Replay barriers are included, so these times are
not native stage percentages. Every completed command output is finite and
bit-exact and inputs are unchanged. The first cost run uses one warmup
command and three samples per block. Several controls drift substantially;
the second run uses 16 warmup commands and five samples per block. Both
complete and all raw data are retained. Neither run has a positive candidate
effect with control spread ≤5%. Apparent positive isolated effects therefore
do not justify a partial integration. No claim about register pressure or
occupancy is made; those counters were not collected.

**Both variants are rejected.** No prefill timing, native single-session
performance campaign or full checkpoint campaign was run for these rejected
candidates. The available full-prefix/checkpoint harness is retained but
not used to claim validation in this campaign. Production inference remains
unchanged. Each run records its own immutable sources and binary; the two
cost harness versions are retained separately.
